# Прошивка imu_to_dxl 0.2.0

[Оригинал документа](README.original.md)

Для изготовленной участником команды платы **STM32G031F8P6 + LSM6DSV16X**. Аппаратная база —
`fanhao375/microduck-replica`, версия `a1f4979c425bd9228622be89f2bfa4d1de7fbde3`
(2026-09-08, с J4/J5 и RX_EN). Первый запуск реальной платы выполнен 2026-09-20: проверены подключение J-Link SWD,
запись прошивки с проверкой считыванием, остановка Keil в `main`, тактирование 64MHz и опрос IMU.
В коротком тесте идентификатор IMU был `0x70`, ready=1, ошибок SPI/FIFO — 0; внешняя шина и сервоприводы ещё не испытаны.

**В 0.2.0 (2026-09-22) протокол шины заменён на Feetech SCS/STS**, с последовательной реализацией [протокола шины](../总线协议.md): ID 200, блок из 15 байт по адресу 56, очередь sync_read. IMU, аппаратный слой и проект Keil не изменены. Все компьютерные тесты и приёмка «моделируемая шина с настоящим кодом протокола» (`Tests/bus_sim_test.py`, критерии `check` из [`tools/imu200`](../../../tools/imu200)) пройдены; прошивка записана в исходную отладочную плату, IMU работает как прежде. **Реальная шина и сервоприводы ещё не испытаны.**
Границы проверки сборки, настольных тестов и первого запуска платы описаны в [VALIDATION.md](VALIDATION.md).

Этот каталог расположен рядом со схемой и PCB; здесь находятся исходники, проект Keil и единственный сохраняемый предварительно собранный файл
[`Build/imu_to_dxl.hex`](Build/imu_to_dxl.hex). Последовательный отладочный пульт [`tools/servo-web`](../../../tools/servo-web) совмещает на одной веб-странице углы суставов от сервоприводов и ориентацию корпуса от IMU; доступны три способа чтения: `--imu-bus` (шина сервоприводов, тот же sync_read, что у контроллера), `--imu-swd` (ST-Link / DAPLink), `--imu-jlink` (J-Link).

Наблюдатели SWD / J-Link декодируют из HEX образ Flash размером **10,724 байт** начиная с `0x08000000`, проверяют SHA-256
`66bc7c532f5a1ad87e3dfff71a4b51f8c4f20840a8f62436874fa5b7c665938e` и сверяют образ на плате.
Только для этой базовой версии допустима проверенная разметка RAM: `sample=0x2000006C` (60 байт),
`tick=0x20000A34` (4 байта), сверенная с MAP версии 0.2.0. Для одной лишь веб-страницы ориентации пересборка не нужна; после изменения прошивки необходимо заново проверить
контрольную сумму Flash, адреса и размеры этих двух символов; читать новую программу по старым адресам нельзя.

Для отладки исходников с точками останова нужно заново собрать `.axf` в своём окружении; сборка также создаёт `.map` и `.bin` для проверки при разработке.
Эти файлы и результаты тестов исключены через `.gitignore` и не включаются в репозиторий.

Поток данных: LSM6DSV16X → SPI1 → STM32 → USART2 + внешний буфер → однопроводная полудуплексная шина → основной контроллер Linux.
Реализован **протокол Feetech SCS/STS, ID 200, 1Mbps**: устройство представляется сервоприводом на общей шине (в 0.1.0 использовался Dynamixel Protocol 2.0).
Код не приводит сервоприводы в движение, не записывает MCU Option Bytes и не сохраняет конфигурацию прошивки во Flash.

**Приёмка на реальной шине**: подключить полудуплексный адаптер (URT-2) и выполнить `python tools/imu200/imu200.py check --port COMx`; 13 критериев взяты из исходников контроллера, и только после их прохождения допускается подключение к роботу. Для электрических проверок (освобождение DE, уровни, измерение T_resp) по-прежнему нужен логический анализатор.

<a id="1-直接开始"></a>
## 1. Быстрый запуск

<a id="keil"></a>
### Keil

1. При использовании J-Link открыть `MDK-ARM/imu_to_dxl_jlink.uvprojx`.
2. В своём Keil выбрать законно установленный Arm Compiler 6 (проверены 6.24 и 6.22; старые версии вроде MDK 5.24 с 6.7 не подходят: заголовки CMSIS 6 требуют ≥ 6.10, иначе возникает ошибка отсутствия `cmsis_clang.h`) и пакет устройства `STM32G031F8Px`.
3. Нажать **F7** для сборки; `Build/imu_to_dxl.hex` — файл для прошивки, `.axf` — для отладки исходников с точками останова.
4. В Debug → Settings выбрать свой J-Link, проверить SWD, алгоритм Flash STM32G0xx 64KB и Run to main.
   `JLinkSettings.JLinkScript` устанавливает скорость **100kHz** после подключения и сброса; сохранить этот файл.
   На первой плате загрузка при 4MHz однажды завершилась ошибкой передачи; для первого подключения рекомендуется проверенная скорость 100kHz.
5. Нажать **Ctrl+F5**, чтобы начать отладку с остановкой в `main`; **F10** — шаг с обходом, **F11** — шаг с заходом, **F5** — продолжить.
   Остановка меняет временные характеристики опроса и шины; непрерывный обмен проверять на полной скорости.

Исходная конфигурация ST-LINK в `MDK-ARM/imu_to_dxl.uvprojx` сохранена. При замене J-Link необходимо заново выбрать отладчик в Debug → Settings.

<a id="vs-code"></a>
### VS Code

Открыть этот каталог в VS Code для редактирования исходников и выполнить приведённую ниже команду сборки во встроенном терминале.
В этом варианте VS Code используется для редактирования, а Keil — для компиляции и аппаратной отладки; для сборки не требуется дополнительно устанавливать CubeMX, CubeIDE или GCC.
Необходимые заголовки CMSIS и драйвер ST IMU входят в исходники, поэтому первая сборка не требует скачивания зависимостей.

Также можно выполнить в терминале PowerShell этого каталога:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Tools\build.ps1
```

Путь компилятора по умолчанию `E:\Keil_v5\ARM\ARMCLANG` приведён только как пример. На другом компьютере указать законно установленный Arm Compiler через `-ToolchainRoot`.
Временный каталог сборки находится в `Build` этого проекта; кешами лицензий ОС и установленных инструментов по-прежнему управляют соответствующие программы.
Сборка заменяет предварительно собранную прошивку в `Build`; чтобы сохранить проверенную базовую версию для веб-страницы, сначала сохранить исходные файлы.

<a id="2-工程内容"></a>
## 2. Состав проекта

| Файл | Содержимое |
|---|---|
| `Core/Inc/board_config.h` | Общие аппаратные переключатели, тактирование, скорость UART и SPI |
| `Core/Src/board.c` | Тактирование, GPIO, SPI, USART, сохранение SWD, миллисекундная/микросекундная шкала времени, сторожевой таймер |
| `Core/Src/imu.c` | Проверка идентификатора, проверка инициализации считыванием, FIFO, сырые данные акселерометра/гироскопа, SFLP, повторные попытки после сбоев |
| `Core/Src/protocol.c` | Ведомое устройство Feetech SCS/STS: разбор кадров (ресинхронизация по контрольной сумме), ответы на команды, очередь sync_read, временные параметры ответа |
| `Core/Src/control_table.c` | Блок из 15 байт по адресу 56, биты состояния, диагностические регистры |
| `Core/Src/main.c` | Планирование главного цикла, команды UART и журнал состояния |
| `Drivers/` | Зафиксированные версии исходников ST/CMSIS и лицензии |
| `MDK-ARM/` | Проект Keil, разметка линковки и скрипт подключения J-Link на малой скорости |
| `Tests/` | Тесты протокола, моделируемого датчика и регистров, работающие без платы; `bus_sim_test.py` собирает настоящий код протокола в DLL и подключает к моделируемой шине для приёмки |

Нет динамической памяти, RTOS и зависимости от HAL. Аппаратный код использует официальные определения регистров ST CMSIS; датчик — официальный платформонезависимый драйвер.
Приём внешней шины STM32 использует кольцевую очередь прерывания, сохраняющую время каждого байта; протокол, опрос и форматирование журнала выполняются в главном цикле.
Передача журнала использует отдельную очередь прерывания и не блокирует приём шины.

<a id="3-默认硬件配置"></a>
## 3. Аппаратная конфигурация по умолчанию

| Функция | Выводы микросхемы / настройка |
|---|---|
| MCU | STM32G031F8P6, TSSOP20, 64KB Flash / 8KB RAM |
| Системная частота | HSI16 → PLL, M=1, N=8, R=2, 64MHz, Flash 2 такта ожидания |
| Внешнее тактирование | `BOARD_USE_HSE_BYPASS=1`, активный генератор X1 16MHz подключён к выводу корпуса 2; при неудачном запуске — возврат к HSI и запись состояния |
| IMU SPI | SPI1 mode3, 8bit, программный CS; 2MHz при 64MHz; PA4=CS, PA5=SCK, PA6=MISO, PA7=MOSI |
| IMU INT | Первая версия опрашивает FIFO; сигналы прерывания PA0/вывода корпуса 15 пока не используются |
| UART шины | USART2, PA2=TX, PA3=RX, AF1, 1Mbps, 8N1; одновыводный режим USART HDSEL не включён |
| DE шины | PA1 → U3.1 `1OE#`, **активный низкий уровень**; управление GPIO, освобождение только после USART TC |
| RX_EN шины | PB7 → U3.7 `2OE`, **активный высокий уровень**; выключен при передаче, PA3 подтянут вверх; PB8 того же вывода корпуса остаётся аналоговым входом |
| Отладочный UART | USART1, PA9/PA10 переназначены через SYSCFG на выводы корпуса 16/17, 115200, 8N1; `BOARD_LOG_UART_SWAP=0` |
| SWD | PA13=SWDIO, PA14=SWCLK; сохранена отладочная функция, действующая после сброса |
| Сторожевой таймер | По умолчанию включён, около 2 секунд; фактическое время зависит от погрешности LSI; заморожен при остановке отладчиком |

При сбое запуска PLL остаётся работа от HSI16; BRR UART и таймер рассчитываются по фактической частоте. SPI при этом снижается до 0.5MHz,
задержка обслуживания увеличивается. Это режим диагностики неисправности: следует проверить состояние тактирования; такая конфигурация не считается прошедшей проверку производительности.

<a id="j3-接线必须以原理图-pdf和实板网络为准"></a>
### Подключение J3 обязательно сверять с [PDF схемы](../imu_to_dxl-原理图.pdf) и цепями реальной платы

| Вывод J3 | Сигнал актуальной схемы | Подключение |
|---|---|---|
| 1 | GND | Общая земля J-Link/ST-LINK/USB-TTL |
| 2 | SWDCLK | J-Link/ST-LINK SWCLK |
| 3 | SWDIO | J-Link/ST-LINK SWDIO |
| 4 | UART_RX, вывод корпуса U1 17 | USB-TTL TX, уровень 3.3V |
| 5 | UART_TX, вывод корпуса U1 16 | USB-TTL RX, уровень 3.3V |
| 6 | 3.3V | Опорное напряжение отладчика; не подключать сюда 5V |

Четыре провода SWD J3 подключаются к выводам **1, 2, 3, 6**; нельзя вставлять старый четырёхконтактный шлейф целиком в выводы 1–4:
вывод 4 — вход UART, его нельзя использовать как питание или опорное напряжение. Перед первым включением проверить соединения по площадкам/цепям EDA.
NRST на J3 не выведен; для подключения under-reset требуется отдельный провод к реальной контрольной точке NRST.
Если у отладчика есть выход питания, нельзя без проверки соединять его параллельно с другим источником; сначала выяснить, это вход VTref или выход питания.

J1/J2: 1=GND, 2=VDD_BUS, 3=DATA; J4/J5: 1=DATA, 2=VDD_BUS, 3=GND.
Для проверки шины нужен однопроводный полудуплексный USB-адаптер; обычный USB-TTL используется только для журнала J3.

<a id="4-imu-行为"></a>
## 4. Работа IMU

- WHO_AM_I должен быть `0x70`. После программного сброса выполняется последовательная настройка с чтением ODR, диапазонов и включения SFLP для проверки.
- Ускорение ±4g, 0.122mg/LSB; гироскоп ±500dps, 17.5mdps/LSB.
- Частота акселерометра, гироскопа, SFLP и пакетирования FIFO — 120Hz, для чтения контроллером при 50Hz.
- Ускорение, гироскоп и кватернион различаются по тегам FIFO; за проход читается не более 16 записей, без предположения, что все три находятся в одной записи.
- При инициализации, ошибке SPI, переполнении FIFO или устаревании данных `ready=0`; автоматическая повторная попытка примерно через 1 секунду.
- Данные недействительны, если gyro или quaternion не обновлялись более 100ms. Даже если главный цикл занят и опрос не выполнен, возраст повторно проверяется при чтении снимка.
- Интерфейс чтения обеспечивает согласованный снимок; ориентация не обновляется в прерывании. Поворот установки датчика оставлен основному контроллеру, чтобы не дублировать официальное преобразование координат.
- Эта версия не сохраняет измеренное смещение; SFLP начинает оценивание из состояния по умолчанию при включении питания. Шестиосевая ориентация не даёт абсолютного направления курса.

Допустимая единичная ориентация `xyz=0,0,0` совпадает с используемым upstream полностью нулевым признаком «не готов». После получения действительной ориентации FIFO только полупрецизионное
представление x устанавливается в отрицательный ноль IEEE `0x8000`, математически оставаясь 0; при настоящей неготовности всегда возвращаются одни нули. Подробности — в описании драйвера и регрессионных тестах.

**Границы обработки сбоев во время работы:** проверенная версия официального контроллера после получения нулевой ориентации может сохранять предыдущую, и её `ready()` автоматически не сбрасывается.
Перед отладкой стояния/движения контроллер должен дополнительно читать диагностические `ready`, счётчик и возраст выборки этой версии и обрабатывать недействительные данные.
Скрипт сбора данных для ПК уже читает эти поля; «плата возвращает нули» не означает, что робот уже умеет автоматически останавливаться.

<a id="5-通信与寄存器"></a>
## 5. Обмен и регистры

Формат кадра `FF FF ID LEN INSTR параметры… CHK`, `CHK = ~(ID+LEN+INSTR+Σпараметры)`; вставки байтов нет, поэтому в полезной нагрузке также встречается `FF FF`: приём завершается по длине, затем проверяется сумма; при ошибке отбрасывается один байт и возобновляется поиск заголовка, так что ложный заголовок в нагрузке не сбивает разбор. Поведение каждой команды описано в [протоколе шины §8](../总线协议.md#8-其它指令怎么应答):

| Команда | Поведение |
|---|---|
| `SYNC_READ 0x82` (широковещательная) | При позиции k в списке: если k=0, передача через 50 µs после окончания команды; если k>0, ожидание кадров ответа предыдущих k устройств (ID находится ранее в списке, правильная длина, 5-й байт не код команды); если предыдущее устройство молчит 1 ms, оно считается отсутствующим и пропускается |
| `PING` / `READ` (адресные) | Кадр состояния / данные, ERROR всегда 0; широковещательный PING без ответа |
| `WRITE` / `REG_WRITE` (адресные) | ACK, содержимое полностью игнорируется (контроллер никогда не пишет в эту плату) |
| `ACTION` `0x06` `0x09` `0x0A` `0x0B` (адресные) | ACK без действия |
| `REBOOT 0x08` | Без ответа, настоящий перезапуск |
| `SYNC_WRITE`, остальные широковещательные | Без ответа |

Временные параметры (все оценочные, требуют измерения, см. протокол шины §5/§12; 50 µs — значение в логике протокола, фактическое время с затратами CPU на разбор и формирование кадра нужно измерить анализатором): T_resp 50 µs; незавершённый кадр отбрасывается при промежутке между байтами более 500 µs; тишина 1 ms при ожидании очереди означает отсутствие предыдущего устройства; если очередь не наступила за 25 ms — отказ; если после назначенного момента передать не удалось ещё 2 ms — отказ, чтобы не занимать шину в следующей транзакции. Перед передачей атомарно повторно проверяются новые данные RX, USART BUSY и флаги ошибок; при занятости этот ответ отменяется.
В прерывании приёма только **переполнение (ORE)** считается неисправностью шины и очищает приём; флаги шума / ошибки кадра лишь подсчитываются, байты принимаются, а ошибочные данные отбрасываются по контрольной сумме. В 0.1.0 очистка выполнялась всегда: один байт с флагом шума уничтожал весь sync_read, и на этом такте терялись все 15 сервоприводов (исправлено после ревью 0.2.0).

**Ставьте ID200 первым в списке Sync Read**, как в официальном `bus.rs`; в середине он тоже отвечает (правила очереди), но при отсутствии предыдущих устройств разбор на контроллере смещается, см. протокол шины §2.

Все многобайтные поля — little-endian.

| Адрес | Байты | Содержимое / права |
|---|---:|---|
| 0 / 1 | по 1 | Версия прошивки 0.2 (основная.дополнительная), не выдаёт себя за сервопривод 3.46 |
| 2 | 1 | END = 0 (little-endian) |
| 3 | 2 | Собственный код модели `0x4D44` |
| 5 / 6 / 8 | по 1 | ID 200 / скорость 0 (1Mbps) / уровень ответов состояния 1 |
| **56** | **15** | **Блок, читаемый контроллером каждый такт**: gyro XYZ (int16, 17.5 mdps/LSB), кватернион XYZ (binary16), счётчик выборок (u8), биты состояния, резерв 0. Исходный порядок осей, без преобразования координат |
| 124 | 6 | gyro XYZ, три int16, ±500dps (диагностика, те же данные, что в блоке) |
| 130 | 6 | quaternion XYZ, три IEEE binary16; W восстанавливает контроллер |
| 136 | 6 | Сырое ускорение XYZ, три int16, ±4g |
| 142 | 1 | Младшие 8 бит счётчика выборок ориентации |
| 143 | 1 | bit0=ready, bit1=configured, bit2=error |
| 144 / 145 | по 1 | WHO_AM_I / код ошибки |
| 146 / 147 | по 1 | Состояние тактирования / включение сторожевого таймера |
| 148 / 152 / 156 | по 4 | Счётчики выборок ориентации / gyro / accel |
| 160 / 164 / 168 | по 4 | uptime_ms / возраст gyro в ms / возраст ориентации в ms |
| 172 / 176 / 180 / 184 | по 4 | Ошибки SPI / переполнения FIFO / недопустимые кватернионы / восстановления |
| 188 / 192 / 196 / 200 | по 4 | Переполнения очереди RX / ошибки UART (шум, кадр, переполнение) / ошибки суммы / недопустимые пакеты |
| 204 / 208 / 212 / 216 | по 4 | Тайм-ауты приёма / действительные принятые пакеты / фактически отправленные пакеты / отменённые ответы |
| 220 / 224 / 228 / 232 | по 4 | Исходное значение причины сброса RCC / частота CPU в Hz / тайм-ауты TX / отброшенные сообщения журнала |
| 236 | 1 | Версия 2 диагностической таблицы регистров этого проекта (протокол Feetech, блок по адресу 56) |
| 240 | 4 | Число пропусков предыдущего устройства, признанного отсутствующим при ожидании sync_read |
| 244 | 4 | Число ответов, отменённых из-за занятости шины, обнаруженной перед передачей |

Остальные адреса 0~255 читаются как 0; на любую запись возвращается ACK без изменений (для переинициализации IMU теперь используется команда `r` UART журнала J3). 56~70 — интерфейс контроллера; 124 и далее — **собственное диагностическое расширение проекта**, совместимость с регистрами напряжения/температуры сервопривода не заявляется.

Биты состояния блока (byte 13): BIT0 — слияние данных не готово (кватернион полностью нулевой); BIT1 — ошибка связи с IMU (SPI/тайм-аут сброса/настройка/устаревшие данные/FIFO); BIT2 — ошибка самопроверки (неверный WHO_AM_I); BIT3 — между двумя чтениями блока было более 4 обновлений (при 120 Hz выборок и 50 Hz чтения обычно 2~3 за чтение).
Коды ошибок см. `imu.h`: 0 — норма, 1 — запуск, 2 — SPI, 3 — идентификатор, 4 — тайм-аут сброса, 5 — настройка, 6 — устаревание, 7 — FIFO, 8 — кватернион.
Состояние тактирования: 0=HSI PLL, 1=HSE PLL, 2=сбой HSE с возвратом к HSI PLL, 3=сбой PLL, HSI16, 4=возврат после сбоя переключения.

<a id="6-板到后的顺序"></a>
## 6. Порядок действий после получения платы

1. Проверить аппаратную версию, ориентацию J3 и питание; сначала включить отдельную плату с ограничением тока, проверить 3.3V, короткие замыкания, нагрев и сброс.
2. Определить STM32 по SWD, загрузить HEX, проверить остановку в main и запуск после сброса и отключения/включения питания.
3. Подключить UART журнала J3, 115200/8N1. Должна появиться версия, затем каждую секунду ready, id, ошибки и данные.
   `s` печатает состояние, `l` переключает периодический журнал, `r` переинициализирует IMU, `?` показывает справку.
4. Проверить WHO_AM_I=0x70, ready=1 и рост счётчика; перевернуть и повернуть плату вокруг трёх осей, проверяя направления ускорения и ориентации.
5. Подключить к шине только IMU (полудуплексный адаптер URT-2 или аналогичный), выполнить `python tools/imu200/imu200.py check --port COMx --only-imu` (опрос только 200), затем подключить сервоприводы и выполнить полный `check`.
6. Логическим анализатором проверить 1Mbps, полярность DE, освобождение после последнего стоп-бита, восстановление RX и наибольшую задержку ответа.
7. Подключить один сервопривод, затем всю шину; ID200 поставить первым. Записывать ошибки, потери пакетов, FIFO и возраст выборок.
8. После реализации обработки отказов контроллером и проверки монтажной ориентации перейти к совместной отладке робота с внешней поддержкой.

<a id="电脑验收工具"></a>
### Инструмент приёмки на компьютере

Для приёмки шины используется [`tools/imu200/imu200.py`](../../../tools/imu200/imu200.py) (`Tools/imu_probe.py` версии 0.1.0 работал по Dynamixel и удалён при смене протокола). Нужны Python 3.10+ и pyserial:

```powershell
python tools/imu200/imu200.py check --port COM5   # 13 项逐条 PASS/FAIL，判据照主控源码
python tools/imu200/imu200.py demo                # 不接硬件，看假小板怎么答
```

Заменить COM5 портом **полудуплексного адаптера шины**; UART журнала J3 не отвечает на эти команды протокола. Журналы сохраняются в `tools/imu200/logs/` (исходные принятые/переданные данные в hex + строка JSONL на кадр).
Нужен установленный работоспособный Python; заглушка запуска Windows Store эти скрипты не выполняет. Для самой сборки прошивки Python не нужен.

<a id="7-验证与已知限制"></a>
## 7. Проверка и известные ограничения

Тестовый код выполняется настоящим компилятором C; тесты SPI/FIFO используют моделируемые регистры и время и не равнозначны испытаниям микросхемы.
После установки MSVC запустить `Tools/test.ps1` в **x64 Native Tools Command Prompt / Developer PowerShell**, чтобы повторить тесты на компьютере.
Для этого `cl` должен быть в PATH; параметром `-PythonExe` можно указать свой Python. При отдельном запуске двух C-тестов `.cmd`
полный путь к своему `vcvars64.bat` также можно передать первым аргументом. Тестовые скрипты не устанавливают компилятор и не подключаются к оборудованию.
Текущие результаты проверки — в `VALIDATION.md`, версии сторонних исходников — в `DEPENDENCIES.md`.

На реальной плате ещё предстоит проверить: питание и сборку, ошибку скорости UART от HSI, режим/фронты/выбор микросхемы SPI, включение TX, электрические уровни шины,
фактическую частоту обновления FIFO, начальную сходимость и оси SFLP, температурный дрейф, восстановление сторожевым таймером и длительную совместную работу на шине.
Успешные программные тесты не заменяют эту приёмку.
